9. Main difference between "Dictator and Lieutenants" and "Integration

   manager" workflows:

In the Integration Manager workflow, there is a single integrator.

   who pulls from developers' public repositories and pushes to the

   blessed repository. In the Dictator and Lieutenants workflow there

   is an additional hierarchical layer: lieutenants each own a

   subsystem and integrate contributions from their group of

   developers, and only the dictator pulls from the lieutenants into

   the final blessed repository. So the dictator workflow inserts

   lieutenants between the developers and the final integrator.

10. How a team of 100 developers benefits from the "Dictator and

Lieutenants' workflow instead of the "Centralized" workflow:

In the centralized workflow, all 100 developers push directly to

    one shared repository. That creates a bottleneck: constant merge.

    conflicts, an unstable main branch, and no clear integration

    responsibility. At that scale it collapses. The Dictator and

Lieutenants' workflow scales because lieutenants each own a

    subsystem, integrate and test contributions from their group

    before passing them up, and only the dictator merges into the

    blessed repository. This distributes the integration load, keeps

The blessed repository is stable and allows parallel workstreams

    without everyone competing for the same main branch.
